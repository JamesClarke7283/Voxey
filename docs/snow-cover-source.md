# Top snow and survival snowball acquisition

Reference: installed Mineclonia source inspected 2026-09-16. `mods/ITEMS/mcl_core/nodes_base.lua` defines the eight top-snow states, placement, collision and drops; `mods/ITEMS/mcl_core/crafting.lua` defines the snow recipes; `mods/ITEMS/mcl_core/functions.lua` defines melting; `mods/CORE/_mcl_autogroup/init.lua` defines tool harvesting; and `mods/CORE/mcl_attached/init.lua` defines unsupported-node drops. The installed copy has no Git metadata. Reference license: [GPL-3.0](licenses/Mineclonia-GPL-3.0.txt).

`SnowCover` reserves IDs 5260–5267 for one through eight layers. Only the first is exposed as an inventory item. Each layer adds one eighth of a block to the visible and selectable height. The first layer is non-colliding; layers two through eight collide with their actual height. The original Voxey snow texture supplies the mesh and inventory icon. Newly generated Frostpine terrain above the shoreline receives a top layer over its existing snowy ground, providing a natural survival acquisition path.

Placing top snow onto an existing layer increases its height up to eight. Placing again on eight layers starts a single layer above, provided that cell is empty. A new layer requires a full solid support block. Partial blocks cannot support it. Block, torch, bucket, plant, door and bed placement replace targeted top snow because the source marks every layer as buildable-to; soil and attachment checks use the support of the replacement cell. Both cells of a bed may contain replaceable snow. This placement handling does not activate a chest or workstation concealed beneath snow. Survival placement consumes one item; creative preserves it. Collision checks prevent raising a layer into the player's body.

Shoveling top snow yields two through nine snowballs, depending on the number of layers. Silk Touch on a shovel instead returns one single-layer snow item per layer. Breaking top snow without a shovel produces no useful drop. A full snow block gives four snowballs, or itself with Silk Touch. Losing support removes the snow and drops its normal snowballs. Water can wash it away, and pistons destroy it rather than pushing it. Three snow blocks in a horizontal crafting-table row make six top-snow items; the existing four-snowball square makes a full snow block. These interactions provide usable ammunition for [throwable snowballs](throwing-source.md).

The installed source's melting ABM explicitly lists the single-layer `mcl_core:snow` node and ice; it does **not** include `snow_2` through `snow_8`. This implementation preserves that distinction. A single snow layer receives a melt attempt every sixteen loaded seconds with a one-in-eight chance. It disappears without drops at artificial light level twelve or higher. Sunlight alone does not melt it. Artificial light reuses the emitter and obstruction adapter described in [pasture lighting](pasture-source.md), excluding the skylight channel.

Melting scans continue over frames with a limit of 128 candidates and four light queries per update, plus a soft 1.5 ms budget. Per-column membership allows unloading without scanning the whole world. Missed unloaded intervals are not caught up. Snow layer IDs persist as ordinary world edits; loading rebuilds the runtime melting index, and world configuration resets its clocks and queues. Loading validates support after applying saved terrain edits, including old saves where ground was mined before natural top snow existed.

Voxey's existing snowy ground block remains its own terrain adaptation. This module does not port weather accumulation, biome-temperature snow formation, or dynamic conversion among the source's snow-covered grass, podzol and mycelium variants. It also does not extend the existing ice-melting behavior.

`tests/snow_cover_checks.gd` checks each layer's geometry and target height, live placement and stacking, special placement handlers, covered bed cells, preservation of interaction targets, support loss, real shovel and Silk Touch harvest paths, recipes, skylight versus artificial-light melting, interval/chance behavior, water/piston removal, bounded candidate scanning, normal cold-column generation and natural harvesting, old-save support reconciliation, actual save/reload, and runtime index unload/reset.
