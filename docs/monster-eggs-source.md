# Infested blocks (monster eggs)

Voxey follows the supplied Mineclonia `mods/ITEMS/mcl_monster_eggs/init.lua`. The implementation is original GDScript using the source as a behaviour reference.

## Why it mattered

An infested block is a trap you cannot see. It **looks identical to its normal counterpart** and hides a silverfish: break it without Silk Touch and the creature comes out at you. That disguise is the entire mechanic — a block that looked different would be no trap at all.

The source registers **six** variants, one per buildable stone block:

| Infested block | Imitates |
|---|---|
| Infested stone | Stone |
| Infested cobblestone | Cobblestone |
| Infested stone bricks | Stone bricks |
| Infested cracked stone bricks | Cracked stone bricks |
| Infested mossy stone bricks | Mossy stone bricks |
| Infested chiseled stone bricks | Chiseled stone bricks |

## The two halves of the rule

| Breaking with | Result |
|---|---|
| Anything but Silk Touch | A **silverfish** appears where the block was |
| Silk Touch | The **plain block** drops, and no silverfish |

The Silk Touch half is what stops a player from carrying a trap home: the infested block itself can never be picked up, only the ordinary block it was imitating.

## The disguise, and a rendering trap

The disguise is subtler than it looks, and getting it wrong would have been invisible in code review. Voxey renders blocks through **two different paths**:

- **Masonry** blocks (cracked, mossy, chiseled bricks) have a per-pixel pattern function.
- **Stone, cobblestone and plain bricks** have no pattern — they are drawn as a noisy base colour resolved from `Nodes.color(id)`.

The first version routed every infested variant through the masonry pattern function. For the three masonry variants that was correct, but for stone, cobblestone and plain bricks it would have returned a *pattern* where the real block has coloured noise, so **infested stone would have looked measurably different from real stone** — defeating the whole feature.

The fix resolves the infested block's colour to its base block inside `Nodes.color`, which covers every render path at once, exactly as doors and trapdoors already resolve to their material's colour. The test asserts `Nodes.color(infested) == Nodes.color(base)` for all six variants, so a future render-path change cannot silently break the disguise.

## An infested block cannot be collected

The source sets `drop = ""` on every infested variant, so an ordinary break yields
the silverfish and **nothing else**; only Silk Touch returns the plain block. Voxey's
`Nodes.drop` did not know about infested blocks, so all six dropped *themselves* —
which would have made the trap a portable weapon a player could pick up and re-arm
rather than a hazard to walk into.

That is the same shape of defect as the colour and the light level: the node's data
was right, and one of its consumers had never been told the node existed. The test
now asserts `Nodes.drop(id) == 0` for all six while still requiring a valid base
block for Silk Touch to return.

## Recorded source gaps

- **Not generated in structures yet.** The source lines the igloo's ladder shaft with a random mix of ordinary and infested bricks (`set_brick`, using `mcl_monster_eggs`), and the strongholds use them too. Voxey's igloo is not built yet, so infested blocks are currently reachable in creative and by placement but are not yet generated by any structure. This is the next consumer.
- **No silverfish spawner interaction.** In the source a silverfish can call nearby infested blocks to convert into more silverfish (`mcl_mobitems` group behaviour). Voxey's silverfish does not yet do this.
- **No stonecutter recipes.** The source explicitly clears `_mcl_stonecutter_recipes` on infested blocks so they cannot be cut. Voxey has no stonecutter, so there is nothing to clear, and the blocks are simply not in any crafting path.
- **Halved hardness is approximated.** The source halves the base block's hardness. Voxey's table carries an explicit hardness per variant rather than computing it, which gives the same values for the six blocks that exist.
